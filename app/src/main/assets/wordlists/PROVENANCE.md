# Wordlist provenance

D13 requires that every dictionary artefact record where it came from and under
what licence, at the time it is added rather than reconstructed later. This is
that record for `de.txt` and `en.txt`.

Both files are generated by [`scripts/build-wordlists.py`](../../../../../scripts/build-wordlists.py),
which documents the filtering. Re-running it against unchanged sources produces
byte-identical output.

## Licence compatibility

This project is GPLv3 (D13), and every source can be distributed under it:

- **igerman98** is GPL-2+, and "or later" allows GPLv3.
- **SCOWL** is permissive and imposes only attribution-style conditions, which
  GPLv3 accommodates.
- **FrequencyWords** content is CC BY-SA 4.0, which Creative Commons has
  declared [one-way compatible with GPLv3](https://creativecommons.org/compatiblelicenses/).
  One-way means the combined artefact travels as GPLv3 and cannot be taken back
  to CC BY-SA. Attribution is given here and in each file's header.

Every generated file repeats its own sources in a comment header, so a copy
that gets separated from this directory still carries its provenance.

## What is in the files

Tab-separated `word<TAB>count`, one per line, after a `#` comment header.
`count` is the number of occurrences in the OpenSubtitles corpus; the keyboard
divides by the file's total to get a comparable weight, which is what lets
candidates from the two languages be ranked against each other (D1, D2).

Lines are sorted by the *folded* form of the word — lowercased, `ß` as `ss`,
accents removed — because the keyboard binary-searches them in that order
rather than sorting 35,000 strings at startup. `WordlistAssetTest` checks the
order against the app's own folding, so the two cannot drift apart silently.

## Known gaps

- **English contractions are reconstructed, not observed.** OpenSubtitles
  tokenisation splits `don't` into `don` and a separate `'t`, so no contraction
  appears as one word anywhere in the frequency list. The 74 English entries
  containing an apostrophe have their counts allocated from the suffix totals in
  `en_full.txt`, in proportion to how often each stem occurs, and that amount is
  subtracted from the stem — see `contractions()` in the build script. Exact
  where the stem is not a word on its own (`didn`, `isn`); an estimate where it
  is (`can`).
- **Possessives are not shipped.** The English dictionary holds 29,467 of them
  and cannot be told apart from the contractions; shipping all of them would
  nearly double the file for forms the apostrophe key already produces. The `'s`
  entries that are here are restricted to pronouns and interrogatives.
- **German has no contractions at all.** Its spelling dictionary contains no
  apostrophe words, so there is nothing to allocate frequencies to; `geht's` is
  handled on the suggestion side instead (D27).
- **German homographs are lowercase.** `zeit`, `leben`, `weg`, `recht` — words
  the flat spelling list records in their lowercase reading — are stored that
  way, so the noun is only offered capitalised when the typist presses shift.
- **No proper nouns to speak of.** Names are in the frequency list but rarely in
  the spelling lists, so they are filtered out. The personal store (D8) is the
  intended answer.
